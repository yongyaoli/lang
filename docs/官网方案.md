# L 语言官方站点方案（`lang` · 静态官网）

> 目标：给 `L`（`lang`）做一套**零构建、零数据库、零第三方依赖**的官方站点，承担「介绍语言 → 安装解释器 → 刷固件 → 上手写第一行代码 → 查文档」的完整链路。
>
> 参考风格：`openclaw.ai`（代码优先、终端感）、`ponytail.dev`（大字号留白、克制动效）、`sindresorhus.com`（极简列表、几乎没有装饰）。

## 一、项目走读结论（官网要讲清楚的事实）

| 项目项 | 实际情况 | 官网呈现方式 |
| :--- | :--- | :--- |
| 定位 | 纯 C99 从零实现的超轻量嵌入式（ESP32）与通用脚本语言 | 首屏一句话主张 + 三条硬指标 |
| 仓库 | `https://github.com/yongyaoli/lang` | 全站右上角固定 GitHub 入口 |
| 双栖运行 | 同一份 `.l` 脚本既能跑在 ESP32（ESP32 / S3 / C3 / C6），也能在 Windows / Linux / macOS 离线仿真 | 首页双栏结构：真机 / 仿真 |
| 体积 | 解释器 + 标准库仅数千行 C，无 lex/yacc/LLVM/第三方库 | 数字徽章：`C99`、`0 deps`、`~百 KB` |
| 编辑器 | `editors/vscode` 已有语法高亮插件 | 「编辑器支持」小节（当前 README 未提，官网补上） |
| 现成资产 | `assets/logo.svg`、`esp32/web_flasher.html`、`esp32/ESP32_GUIDE.md`、`L_EBNF.md`、`tests/` | 直接复用，不重做素材 |
| 发布 | 仅 `.github/workflows/esp32-firmware.yml` 发布固件 `.bin`；PC 安装包靠本地 `scripts/package.ps1` | ⚠️ 需补 release 工作流，否则官网下载区没有 Windows 安装包可下 |

### 上站前必须先修的 7 个一致性问题

这些问题会直接体现在官网文案里，不修就会「官网说一套、仓库是另一套」：

1. **版本号三处不一致**：`version.h` 为 `0.1.3.202611092011`，最新 tag 为 `v0.2.0`，README 徽章写 `0.1.0`。→ 统一为 tag 驱动，官网只读一处。
2. **README 一行编译命令过时**：缺 `bytecode.c compiler.c vm.c`，Windows 还需 `-lwininet -lws2_32`；`scripts/package.ps1` 里的命令才是真实可用的。官网安装页必须照抄**实测通过**的命令（分 Windows / Linux / macOS 三栏）。
3. **测试数量对不上**：徽章 `17/17`，README 正文写「18 组」，`tests/` 实际有 `01`–`19` 共 19 组。→ 统一为实际数字。
4. **`l_script` 分区大小对不上**：`partitions.csv` 是 `128K`，`改进.md` 与 README 写 `64KB`。→ 以 `partitions.csv` 为准。
5. **C6 缺失**：代码已支持 `CONFIG_IDF_TARGET_ESP32C6`，README 也列了 C6，但 CI matrix 只有 `esp32 / esp32c3 / esp32s3`。→ 官网固件区先只放 3 个可下载的，或补 CI。
6. **没有 LICENSE 文件**：官网页脚与「开源协议」小节无内容可写。→ 建议补 `LICENSE`（MIT 或 Apache-2.0 均可，需作者定）。
7. **`assets/logo.svg` 注释是乱码**（GBK 被当 UTF-8 保存）：不影响渲染，但建议清一次。

> 另：README 里 `mermaid` 图表在静态页面上不会渲染，官网必须换成 CSS/SVG 手绘图或直接省略。

## 二、站点形态与技术选型

### 2.1 三条硬约束的落地方式

| 约束 | 方案 |
| :--- | :--- |
| 静态化、不想编译 | **纯 HTML + 单文件 CSS + 原生 ES5/ES6 JS**。无 npm、无打包、无框架、无 Node。改完直接推仓库即可上线。 |
| 不使用数据库 | 无后端、无 API 服务。版本信息用一份手改的 `assets/js/releases.js` 常量；可选地用 GitHub 公共 API 做「版本自动同步」增强，失败自动降级到常量。 |
| 简约大方 | 无外部字体、无 CDN、无图片（除 logo）、无阴影重色块。靠排版、留白、1px 细线分割。 |

**关键取舍：所有数据用 `.js` 而不是 `.json`。**
因为 `fetch('releases.json')` 在 `file://` 协议下会被浏览器拦截。写成 `assets/js/releases.js`（`const L_RELEASES = {...}`）后，**双击 `index.html` 就能完整预览整站**，同样也能在 Pages 上跑。

### 2.2 页面清单（6 页 + 2 个附加）

| 文件 | 页面 | 职责 | 预估篇幅 |
| :--- | :--- | :--- | :--- |
| `index.html` | 首页 | 一句话说清「是什么 / 为什么要用 / 30 秒上手」 | 1 屏半 + 5 个区块 |
| `language.html` | 语言 | 语法总览：类型、运算符、控制流、闭包、异常、import、错误定位 | 长文 |
| `install.html` | 安装 | Windows 安装包 / 便携包 / Linux & macOS 脚本 / 源码编译 / PATH 验证 | 中 |
| `firmware.html` | 固件 | 三种芯片固件下载 + 首次刷机 3 步 + 日常 `upload()` 烧录 | 中 |
| `usage.html` | 使用 | REPL、CLI 参数表、`upload/connect`、PC 仿真、常见问题 | 中 |
| `docs.html` | 文档 | 索引页：链到 `L_EBNF.md`、`ESP32_GUIDE.md`、标准库/硬件 API 速查 | 短 |

## 三、视觉方案

### 3.1 设计语言

> **一句话：白纸、黑字、一根细线、一种蓝。**

- **排版优先**：首屏只有 `L` 标识、一句主张、两个按钮、一段终端命令。没有插画、没有渐变背景、没有卡片堆叠。
- **等宽字体承担「技术感」**：所有代码块、版本号、标签、按钮上的命令都用等宽；正文用系统无衬线。
- **1px 细线代替卡片投影**：区块之间用 `border-top` 分割，`hover` 只做透明度/下划线变化。
- **动效只有 120ms 的颜色与位移**，并尊重 `prefers-reduced-motion`。

## 四、各页面内容规格

### 4.1 首页 `index.html`

1. **Hero**：标题 / 主张 / 双 CTA / 一行平台徽章 / 安装命令块（带复制按钮，按 `navigator.userAgent` 自动切 Windows·macOS·Linux 三个 tab）。
2. **三十秒上手**：左文右码的 8 行示例（用 README「30 秒直观体验」精简版，去掉 I2C 与 try/catch，保证一眼看懂）。
3. **为什么是 L**：4 条，每条 `标题 + 一句话 + 代码/数字`。关键词：零依赖、双栖、裸 Flash 免文件系统、`[文件:行:列]` 报错。
4. **硬件对象一览**：7 个对象名做等宽标签墙（`Pin` `PWM` `ADC` `I2C` `SPI` `UART` `bytes`），点标签跳到 `language.html#hw`。
5. **安装 / 固件 分流**：两块并排，各一句话 + 一个按钮，不重复正文。
6. **文档索引**：4 行链接列表（EBNF / ESP32 指南 / 语言参考 / 使用说明），`hover` 整行变底色。
7. **页脚**：GitHub、版本、协议、更新日期。

### 4.2 语言 `language.html`

按 README 的章节顺序，压缩成「可扫读」的结构，每节配一段 5~12 行代码：

- 类型表（`int / float / bool / nil / string / bytes / array / map / function`）——**用表格，不做卡片**
- 运算符与整除语义（`7 / 2 == 3` 要点出来，避免 C 习惯踩坑）
- 控制流（`if` 免括号、`for`、`while`、`break/continue`）
- 闭包与一等函数
- `try / catch / throw` + **错误输出示例（深色代码块 + `^` 指示符）**，这是项目最有说服力的部分，给足版面
- `import`（内置 `"esp32"` 与本地 `.l`）
- 硬件 API 速查（`<details>` 折叠 6 个外设类，避免页面过长）
- 页面底部：指向 `L_EBNF.md` 与 `help()` 提示

### 4.3 安装 `install.html`

三段式，每段都是「一句结论 + 命令块 + 一行验证」：

| 区块 | 内容 |
| :--- | :--- |
| Windows | ① 安装包 `lang-setup-windows-x86_64.exe`（双击、自动写 PATH、可在「应用和功能」卸载）；② 便携包 `lang-windows-x86_64.zip`；③ 脚本安装 `install.ps1` |
| Linux / macOS | `bash ./scripts/install.sh`（说明：有 sudo 装 `/usr/local/bin`，否则回退 `~/.local/bin` 并写 shell rc） |
| 源码编译 | 三栏 tab，命令与 `scripts/package.ps1` 保持一致（含 `bytecode.c compiler.c vm.c`） |
| 验证 | `l --version`、`l`、`l main.l` 三行输出示例 |
| 卸载 | `uninstall.ps1` / `uninstall.sh` 各一行 |

> 下载按钮统一指向 GitHub Release 资源；若资源暂缺（见第一章第 7 条），按钮文案降级为「前往 Releases 下载」，**不要留死链**。

### 4.4 固件 `firmware.html`

- 顶部一句：**每块板子只需刷一次底包固件；之后改脚本 0.2 秒烧录，不用再刷固件。**
- 三张并排下载卡（等宽、细线、无投影）：

  | 芯片 | 文件 | 刷写地址 | 状态 |
  | :--- | :--- | :--- | :--- |
  | ESP32 | `l-esp32-merged.bin` | `0x0` | 可直接下 |
  | ESP32-C3 | `l-esp32c3-merged.bin` | `0x0` | 可直接下 |
  | ESP32-S3 | `l-esp32s3-merged.bin` | `0x0` | 可直接下 |
  | ESP32-C6 | 待 CI 补矩阵 | `0x0` | 标注「构建中」 |

- **首次刷机 3 步**（编号列表，不写长段落）：① 下 `.bin`；② Chrome/Edge 打开网页刷机工具，地址填 `0x0`；③ 选文件、点 Flash。
- 备用命令行：`esptool.py --port COM3 write_flash 0x0 l-esp32-merged.bin`
- **日常烧录**：REPL `upload("COM3", "main.l")` / CLI `l -u COM3 main.l` / 网页工作台，三选一，代码块并列。
- 链接到 `esp32/ESP32_GUIDE.md` 与 `esp32/web_flasher.html`。
- 阶段二把 `web_flasher.html` 升级成 `flash.html`：内置 `esptool-js`（本地 vendored，不走 CDN），浏览器里直接完成「刷固件 + 传脚本 + 串口终端」，这是本站最有传播力的一个功能。

### 4.5 使用 `usage.html`

- REPL 会话示例（复制 README 那段带版本号的输出，但改成 `L 0.2.0`）
- CLI 参数表：`l` / `l main.l` / `-p` / `-u` / `-s` / `-h` / `-v`
- `help()` 家族示例
- PC 离线仿真：`upload("sim", "main.l")` + `ESP32.set_chip("ESP32-C3")`
- 常见问题 `<details>` 折叠：串口不出现、CRC32 校验失败、引脚被拦截、Flash 分区大小、GPIO 6~11 为什么不能输出

### 4.6 下载清单的数据结构

`assets/js/releases.js`（唯一需要手改的文件）：

```js
window.L_RELEASES = {
  version: "v0.2.0",
  date: "2026-11-09",
  repo: "https://github.com/yongyaoli/lang",
  assets: {
    winSetup:  { name: "lang-setup-windows-x86_64.exe", size: "—", sha256: "—" },
    winPortable:{ name: "lang-windows-x86_64.zip",      size: "—", sha256: "—" },
    unix:      { name: "lang-unix.zip",                 size: "—", sha256: "—" },
    fwEsp32:   { name: "l-esp32-merged.bin",    size: "—", sha256: "—" },
    fwEsp32c3: { name: "l-esp32c3-merged.bin",  size: "—", sha256: "—" },
    fwEsp32s3: { name: "l-esp32s3-merged.bin",  size: "—", sha256: "—" }
  }
};
```

页面渲染规则：`assets/src` 存在 → 渲染 `…/releases/download/{version}/{name}` 直链 + 大小 + SHA256 悬浮提示；不存在 → 渲染 `…/releases/latest` 并提示「请在 Releases 页选择对应文件」。

**可选增强** `latest-sync.js`：仅当 `location.protocol` 为 `http/https` 时请求 `api.github.com/repos/yongyaoli/lang/releases/latest`，成功后替换版本号并把结果写 `localStorage` 缓存 6 小时；任何异常都静默失败。这样「官网版本号自动跟上 tag」，但离线打开依然可用。

## 五、部署与维护

| 方案 | 操作 | 是否算「编译」 |
| :--- | :--- | :--- |
| **GitHub Pages（分支部署，推荐）** | 仓库 Settings → Pages → Source 选 `main` / `site` 目录，保存即上线 | 否，纯文件托管 |
| GitHub Pages（Actions） | `actions/upload-pages-artifact` + `deploy-pages`，无任何构建步骤 | 否，仅上传静态文件 |
| Cloudflare Pages / Netlify | 直接把 `site/` 拖进去，Build command 留空 | 否 |

- 上线必带 `.nojekyll`（否则 `_` 开头资源可能被忽略）。
- 自定义域名：`site/CNAME` 一行域名 + DNS `CNAME` 指向 `yongyaoli.github.io`。
- 本地预览：双击 `index.html` 即可（全站不依赖 fetch）；或 `python -m http.server 8000 -d site`。
- 发版流程（3 步）：`bump_version.ps1` 改版本 → 打 tag 触发固件 CI → 改 `releases.js` 的 `version`/`date`/`sha256` 三行。

### 建议同步补的两个工作流

1. `.github/workflows/release-pc.yml`：tag 时在 `windows-latest` 跑 `scripts/package.ps1`，在 `ubuntu/macos` 打 `lang-unix.zip`，连同 `SHA256SUMS.txt` 一起 `gh release upload`。**没有它，官网 Windows 下载按钮永远是死链。**
2. `.github/workflows/pages.yml`（可选）：push `main` 后自动部署 `site/`。

## 八、明确不做的事

- 不引入 React/Vue/Astro/Tailwind，不引入 npm/rollup/vite（违背「不想编译」）。
- 不做 CMS / 后台 / 数据库 / 登录 / 评论。
- 不做站内全文搜索（站点规模不需要，`Ctrl+F` 足够；真要做得引入轻量索引，收益不划算）。
- 不做自动 i18n 切换（英文用独立目录，避免运行时逻辑）。
- 不加载第三方统计与 Cookie 追踪（也就无需 Cookie 同意弹窗）。
