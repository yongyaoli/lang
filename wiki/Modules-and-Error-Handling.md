# 模块系统与异常安全

在物联网和嵌入式生产环境中，系统的**健壮性与故障自恢复能力**至关重要。L 语言设计了严谨的模块导入系统与精确的异常拦截回溯体系。

---

## 1. 模块导入系统 (`import`)

L 语言内置了轻量级、防重复加载的模块加载机制：

```l
// 导入标准模块
import "json";
import "mqtt";
import "ota";

// 序列化与反序列化
let data = {"temp": 28.5, "status": "ok"};
let json_str = JSON.stringify(data);
print("JSON 串:", json_str);

let obj = JSON.parse(json_str);
print("解析回温度:", obj.temp);
```

### 核心内置模块清单：
* **`json`**：极速紧凑 JSON 解析与字符串序列化；
* **`mqtt`**：支持 MQTT 3.1.1 协议的工业物联网客户端；
* **`ota`**：支持空中升级、校验和与 Flash 热重载的无线管理库；
* **`fs`**：轻量级虚拟与本地文件读写系统。

---

## 2. 结构化异常捕获 (`try / catch / throw`)

嵌入式设备最怕“因为一个传感器偶发读失败，导致整机看门狗重启”。L 语言支持全功能的异常安全拦截机制：

```l
try {
    print("尝试连接网络并读取传感器...");
    // 假设网络连接超时
    throw "网络连接超时 (5000ms)";
} catch (e) {
    print("捕获到异常:", e);
    print("系统自动切换至离线离线降级策略...");
}
```

### 异常对象的精确定位能力
当异常抛出时，L 语言会自动抓取运行时的调用栈，并输出：
1. **出错文件与行列号**：`[<main.l>:15:10]`
2. **出错源代码片段**与 `^` 定位指示符
3. **完整的函数调用链回溯 (Call Stack Traceback)**

## 3. 硬件安全护栏机制

ESP32 内部有部分引脚被外围总线深度占用（例如 ESP32 的 GPIO 6~11 被板载 SPI Flash 占用）。如果初学者写了 `Pin(6, "out")`，传统 C 语言会导致芯片瞬间硬件锁死。

而在 L 语言中：
* 底层内置了**各芯片型号（ESP32 / S3 / C3 / C6）的安全引脚字典**；
* 当试图对 Flash 引脚设为输出，或者对仅支持输入的引脚（如 GPIO 34~39）写输出时，运行时会**主动抛出可捕获的致命保护异常**，彻底保护板载 Flash 与芯片不被烧毁变砖！
