Firmware

Flash once, script forever

Each board needs the L base firmware exactly once. After that, .l scripts are written over serial in 0.2 seconds and run immediately — no rebuild, no filesystem.

01 Download

Choose your chip

All files are merged single binaries: write at 0x0 and the bootloader, partition table and application are all in place.

ESP32 l-esp32-merged.bin classic ESP32 · offset 0x0 ESP32-C3 l-esp32c3-merged.bin RISC-V · offset 0x0 ESP32-S3 l-esp32s3-merged.bin dual-core LX7 · offset 0x0

About ESP32-C6: the interpreter and firmware project already support C6 (Wi-Fi 6 / BLE / Thread), but the CI matrix currently publishes ESP32, C3 and S3 only. Build C6 locally with ESP-IDF using the guide below.

02 First flash

Three steps

You only need Chrome or Edge. No ESP-IDF, no Python.

  1. Download the .bin for your chip

    Check the silkscreen, or read the chip model from the serial log after plugging in.

  2. Open the web flasher and connect

    Use Chrome / Edge with Espressif's ESP Web Flasher, then pick the board's serial port.

  3. Set the flash offset to 0x0 and press Flash

    When it finishes the board resets straight into the L REPL.

Open web flasher Repo toolbox

From the command line

Already have esptool.py? One command:

esptool
esptool.py --port COM3 write_flash 0x0 l-esp32-merged.bin

03 Daily uploads

Change a script, not a firmware

Three ways to upload. The partition is erased, written, then verified with IEEE 802.3 CRC32 before the script runs.

From the REPL

>>>
ports();
upload("COM3", "main.l");
connect("COM3");

From the CLI

terminal
l -p                 # list ports
l -u COM3 main.l     # upload and run
l -s COM3            # remote terminal

From the browser

Web Serial
// paste a script, click upload
// same __L_UPLOAD_BEGIN__ protocol
pin(2).on();
print(ESP32.chip());

The uploader waits for __L_UPLOAD_READY__, sends 64-byte chunks and normalizes line endings to LF so the CRC32 always matches.

04 Partition

Where the script lives

A custom data partition l_script (subtype 0x99) holds the script. No filesystem is mounted.

PartitionTypeSize
nvsdata / nvs0x6000
phy_initdata / phy0x1000
factoryapp / factory2M
l_scriptdata / 0x99128K

The 16-byte header holds magic (LSCR for source, LBC1 for bytecode), length, crc32 and flags. On boot, a valid magic plus checksum means the script executes straight from the esp_partition_mmap window.

Lexing, error reporting and bytecode execution all read the flash mapping, so all 320 KB of SRAM stay available to your logic.
