04 Source

How the code is organized

The pipeline is easy to follow: lexer → parser → AST → tree-walking interpreter or bytecode VM, with a value system and mark-sweep GC underneath.

lang/
src/
├─ include/     public headers (l_config.h / l_hal.h ...)
├─ core/        interpreter core
│   lexer.c     tokenizer (0x / 0b literals)
│   ast.c       syntax tree nodes
│   parser.c    recursive descent parser
│   value.c     dynamic value system
│   gc.c        mark-sweep collector
│   interp.c    evaluator, dispatch, errors
│   builtins.c  builtins and help()
│   bytecode.c  bytecode serialization
│   compiler.c  source to bytecode
│   vm.c        stack virtual machine
├─ stdlib/      standard library (io / net / math / hw / time / sys ...)
└─ main/
    main.c      CLI entry point

Regression tests

Every .l in tests/ has a matching .out with expected output, covering syntax, closures, collections, GC, bytecode, hardware objects and networking.

PowerShell
powershell -ExecutionPolicy Bypass -File .\run_tests.ps1

Editor support

A VS Code extension with TextMate grammar for .l ships in editors/vscode and installs locally.

PowerShell
powershell -ExecutionPolicy Bypass -File .\scripts\install_vscode_ext.ps1
