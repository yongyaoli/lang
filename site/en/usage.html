Usage

REPL, CLI and offline simulation

Run l with no arguments to enter the REPL: semicolons are optional, multi-line { ... } blocks are detected, and hardware objects can be poked interactively.

01 Interactive

Built-in help is the manual

help() lists every function group, constant and ESP32 shortcut; help("name") shows one group; help(object) lists all methods.

simulate.l
>>> upload("sim", "main.l")   // dry-run flash + CRC32
>>> ESP32.set_chip("ESP32-C3")
>>> ADC(34).write_sim(2048)
>>> ADC(34).read_mv()

daily.sh
l -p                    # which port?
l -u COM3 main.l        # push changes

l -c app.l -o app.lc    # compile
l app.lc                # run
l -d app.l              # inspect

Exit codes: 0 success, 65 syntax error, 70 runtime error, 74 unreadable file — handy in CI or watchdog scripts.

03 Simulation

Write code without a board

On PC the HAL switches to host-sim: GPIO records state, I2C accepts virtual slaves, ADC and UART take injected data. Your script stays unchanged.

sim.l
ESP32.set_chip("ESP32-C3");        // apply C3 pin rules
print(ESP32.pins());               // usable / input-only / flash

let i2c = I2C(0, 8, 9, 400000);
i2c.sim_device(0x3C);              // virtual OLED slave
i2c.write_reg(0x3C, 0x00, bytes([0xAF]));

let uart = UART(1, 115200);
uart.sim_input("OK\r\n");
print(uart.read_str());

pin(2).on();
print("GPIO2 =", pin(2).value());   // 1

The same file, uploaded with l -u COM3 main.l, drives real hardware.

l sim.lsimulate: verify logic and pin legality
l -u COM3 sim.lreal board: same source, no edits

Simulation still enforces the pin guard: flash pins (GPIO 6–11) and input-only pins (GPIO 34–39) are rejected the same way.

04 FAQ

Where people get stuck

Command not found after installing

Open a new terminal window first — PATH changes do not reach already-running shells. Check with where l (Windows) or which l (macOS / Linux).

The port list is empty

Most boards need a USB-serial driver (CP210x or CH34x). Make sure the cable supports data, not just charging. On macOS the device usually shows up as /dev/cu.usbserial-* or /dev/cu.wchusbserial*.

Upload fails with a CRC32 mismatch

Usually an unstable baud rate or dropped bytes. Try a shorter cable, another USB port, or a lower baud rate. Before uploading, the tool sends Ctrl+C to interrupt the running script and normalizes line endings to LF.

Why can't GPIO 6–11 be outputs?

They are wired to the internal SPI flash; driving them can brick the chip mid-fetch. L rejects this at Pin() construction instead of letting the board hang. Input-only pins (GPIO 34–39) are read-only for the same reason.

How large can a script be, and does it survive power loss?

Scripts live in the l_script partition (128 KB) with a length and CRC32 header, so they persist. Writes erase, program and verify; a failed checksum never runs.

Do I need a filesystem?

No. The default is a raw flash partition with MMU mapping and zero SRAM copy. LittleFS is opt-in, only when you need multi-file import or runtime config files.
