Usage

REPL、命令行与离线仿真

不带参数运行 l 进入交互模式：语句末尾的分号可省略，跨行 { ... } 代码块会自动识别，硬件对象可以边写边试。

01 交互模式

边写边跑的 REPL

>>>
L 0.1.9 (Nov  9 2026) [GCC 16.2.0 64 bit] on win32
Type "help", "copyright", "license" or "exit" for more information.
ESP32 快捷命令: ports() | upload("COM3", "main.l") | connect("COM3") | help("esp32")

>>> help()
>>> help("esp32")
>>> help(ESP32)
>>> ports()
["COM3"]
>>> upload("COM3", "main.l")
>>> connect("COM3")
[按 Ctrl+] 或输入 .exit 退出板端终端]

内置帮助就是离线手册

help() 列出全部函数分组、常量与 ESP32 快捷操作；help("名字") 查看某一组；help(对象) 查看对象的全部方法。

simulate.l
>>> upload("sim", "main.l")   // 演练烧录 + CRC32 校验
>>> ESP32.set_chip("ESP32-C3") // 切换目标芯片
>>> ADC(34).write_sim(2048)    // 注入模拟采样值
>>> ADC(34).read_mv()

02 命令行

参数一览

命令作用
l进入交互模式（REPL）
l main.l [参数...]运行脚本，参数可用 sys_args() 读取
l -e "代码"直接在命令行执行语句
l -p, --ports扫描并列出本机串口
l -u, --upload COM3 main.l通过串口烧录脚本到裸分区并运行
l -s, --serial COM3 [波特率]连接板端交互终端，默认 115200
l -c main.l [-o main.lc]编译为紧凑字节码文件
l main.lc直接运行预编译字节码
l --vm main.l强制用栈式虚拟机执行
l -d, --disasm main.l反汇编查看单字节操作码序列
l -h / l -v帮助 / 版本号
daily.sh
l -p                    # 我是哪个口？
l -u COM3 main.l        # 改完就传
l -s COM3               # 看板子日志
bytecode.sh
l -c app.l -o app.lc    # 编译
l app.lc                # 运行
l -d app.l              # 看指令

退出码：0 成功、65 语法错误、70 运行时错误、74 文件无法读取，便于在 CI 或守护脚本里判断。

03 离线仿真

没有开发板也能写

PC 上运行时，HAL 会切换到 host-sim：GPIO 记录状态、I2C 可以注册模拟从机、ADC / UART 可以注入数据，脚本逻辑完全不用改。

sim.l
ESP32.set_chip("ESP32-C3");        // 套用 C3 的引脚规则
print(ESP32.pins());               // 可用 / 仅输入 / Flash 引脚

let i2c = I2C(0, 8, 9, 400000);
i2c.sim_device(0x3C);              // 注册虚拟 OLED 从机
i2c.write_reg(0x3C, 0x00, bytes([0xAF]));

let uart = UART(1, 115200);
uart.sim_input("OK\r\n");
print(uart.read_str());

pin(2).on();
print("GPIO2 =", pin(2).value());   // 1

同样的脚本，插上板子用 l -u COM3 main.l 烧录就是真机行为。

l sim.lPC 仿真：验证逻辑与引脚合法性
l -u COM3 sim.l真机：同一份源码直接烧录

仿真模式下误用 Flash 引脚（GPIO 6~11）或把仅输入脚（GPIO 34~39）设为输出，同样会被拦截报错。

04 常见问题

可能卡住你的地方

装了但终端提示「找不到 l 命令」

确认使用的是安装后新开的终端窗口。Windows 用 where l，macOS / Linux 用 which l 检查解析路径；仍在旧窗口里的话，PATH 不会更新。

串口列表是空的

多数开发板需要安装 USB 转串口驱动（CP210x 或 CH34x）。若板子只有 USB-OTG 口，确认数据线支持传输而非仅充电。macOS 上串口名通常是 /dev/cu.usbserial-* 或 /dev/cu.wchusbserial*。

烧录时报 CRC32 校验失败

通常是串口波特率不稳或传输过程中有丢字节。换一根短一些的数据线、换 USB 口，或降低波特率重试。上传前工具会先发 Ctrl+C 打断板端正在运行的脚本，并统一换行为 LF。

为什么 GPIO 6~11 不能设为输出？

这些引脚连接内部 SPI Flash，驱动它们会让芯片无法取指而死机变砖。L 在 Pin() 构造时就会拦住并报错，而不是等板子挂掉。仅输入引脚（GPIO 34~39）同理，只允许读。

脚本能存多大？断电会丢吗？

脚本存在 l_script 分区（当前 128 KB），带长度与 CRC32 头部，断电不丢。写入采用先擦除后写入再校验，校验失败不会执行旧内容以外的任何东西。

需要挂载文件系统吗？

不需要。默认方案是裸 Flash 分区 + MMU 映射，零 SRAM 拷贝。只有在需要多文件 import 或运行时配置文件时，才按需打开 LittleFS。
